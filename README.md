# 观照 · 多视角调研

做项目选型时，问 AI 可以很快得到建议。接下来还有一串事：把自己的条件讲清楚，找资料，核对出处，再判断这些信息到底会不会影响选择。

我做观照，是想把这些工作放进一次调研里。用户提出问题，观照先整理需求，再围绕不同场景查资料，把出处、适用条件和参考价值一起留在报告中。重点是帮用户看见值得比较的选择，少做重复的搜索和筛选。

## 为什么做观照

观照延续了我的另一个项目：[认知视角检查器](https://github.com/EversiusJade/cognitive-perspective-check)。这个 Skill 用来检查用户和 AI 的预设，补齐会改变判断的背景，再对照不同视角。

框架能帮助明确“该问什么”，资料查证还需要工具。观照接入了百炼模型和 Tavily 搜索、正文读取，把这套思考流程接到实际检索上。每条资料都要回答：它从哪里来，回应了哪个问题，对选择有什么用。

AI 对话也能联网搜索。观照把需求检查、场景比较和出处整理放在同一个流程里，方便用户检查建议与自己条件之间的关系。第一版聚焦 AI 项目选题、工具比较和软件实现方案。

## 拿一个问题举例

> 我想做一个用于投实习的 AI 项目，应该用百炼工作流，还是借助 AI 写 Python？

这是一个用来说明流程的例子。观照会先区分：用户要展示产品设计，还是希望练习工程实现？能投入多少时间？作品需要别人直接访问吗？已有背景足够时直接开始，缺少关键条件时再补问。

这些条件决定检索方向。同一份部署文档，对“先做出原型”和“持续对外提供服务”的参考价值不同。报告会把相关原文和链接放在对应判断旁边，说明不同路线适合什么情况，以及哪些新条件会改变建议。

## 一次调研怎么走

1. **理解需求。** 整理目标、限制、已知情况和偏好，标出用户与 AI 各自的假设。
2. **选择视角。** 找出会影响行动的不同场景，确定需要查证的问题。
3. **搜索和读正文。** 模型选择工具，程序执行 Tavily 请求，保存资料与选取理由。
4. **整理报告。** 事实关联原文片段和网页链接，方案关联依据；资料不足的地方留下待查项。

页面可以查看执行进度、回看证据、停止调研，也可以下载 Markdown 报告。

## 运行

需要 Python 3.11 或以上版本。在仓库目录创建并激活虚拟环境，然后执行：

```sh
python -m pip install .
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765`，可先查看固定示例。联网调研需要在项目根目录的 `.env` 中填写以下配置，保存后重启：

```dotenv
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_API_KEY=
TAVILY_API_KEY=
```

上面使用百炼中国内地接口，模型密钥需要属于对应地域；Tavily 使用自己的搜索密钥。密钥保存在服务端，`.env` 不提交到仓库。联网时，问题和背景交给模型处理，搜索词和读取地址交给 Tavily。

云端入口使用 `python -m app.cloud_main`，配置见 [Render 部署说明](docs/Render免费部署.md)。技术栈是 Python、FastAPI、SQLite 和原生 HTML/CSS/JavaScript。

单次请求上限为模型 6 次、搜索 2 次、正文读取 3 次，失败与重试也计入。模型和搜索按各自服务计费；云端试用另设开放截止时间和任务名额。临时磁盘回收会清空记录与计数，持续开放需要持久化额度。
